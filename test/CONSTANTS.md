# test/CONSTANTS.md — 常数台账与机制清单

> **为何有这份东西：** 2026-10-24 清点发现——同一组网络参数在 27 个脚本里被各抄 10~25 份；
> `grow_goal.py` 一开场就带了 37 个常数，比它替代的 `grow_world.py`（36 个）还多。
> 而 `design.md` §0.3 第 5 条写的是：**不发明新参数——每个常量要么是需求给的，要么有文献出处。**

## 1. 清点（2026-10-24，改前）

| 量 | 值 |
|---|---|
| 常数定义总数（含重复） | **584** |
| 唯一名字 | **161** |
| 重复定义 ≥ 3 次的名字 | **56 个（35%）** |
| 重复最重的 | `V_TH` 27 次 / `N` 25 / `DECAY_V` 25 / `P_GLOBAL` 16 / `N_E` 15 / `OUT_RATE` 15 |
| 死常数（定义但不使用） | **0**（在 `grow_goal` / `grow_world` 中） |

**结论：**问题不是「定义了不用」，而是**重复 + 派生写死 + 纯拍**。
改一个网络参数要改 10~25 处，而且抄的过程中已经漂移（`W_MAX` 10 次里有 `W_MAX_E/W_MAX_I` 两种形态，`TAU` 14 次各不相同）。

## 2. 分类标准（在 `net.py` 里逐行标注）

| 标签 | 含义 | 处理 |
|---|---|---|
| `[标定]` | §11.4.0 手扫标定，有实测数字 | 保留；改它要重跑标定 |
| `[约定]` | 归一化约定（阈值=1，其余相对它） | 保留；不是旋钮 |
| `[派生]` | 由其它常数算出 | **不得作为可调旋钮**（改上游） |
| `[需求]` | 由设计/任务定义（环境设计） | 保留；改它等于改任务 |
| `[拍]` | 无依据，取一个能跑的值 | 保留但**记账**；下一轮优先标定或删 |

### 两条最严重的

1. **「环境 = 本机」被我自己换成了人工世界。** 场次四 §五明写「环境：本机（命令 3 秒 / 测试 10 秒 / git 可回退）」，
   而我直接用了 2D 目标世界，理由是「脉冲网做不了语义任务」—— **这是真约束，但应该提请，不是自己定**。
   后果：**「压力」本质上仍是设计的，不是环境给的**（`design.md` §9.2 的「压力由环境提供」未成立）。
2. **隔离（写入局部性）完全没碰。** §9.2 三要素之一，`design.md` §2.4 第 2 条（LSL 的 retention 76.6% → 96.6%）
   就是它。现在是一个全局 `m` → **所有边同样更新**，等于「无差别覆盖」，正是 §9.2 说「最容易漏」的那一项。

### 本轮新增的一个重犯错

迹的时间常数：`grow_talk`（§16.10）已经用数据证明「`delay=50` 学不到，因为 τ=20」，
我在 `grow_goal` 里又用了 τ=20，而 episode 是 120 步——**奖励到达时迹已衰减到 0.007**。
改成 τ=100 后 A 组 +3.8 pp（8.7% → 12.5%），但仍低于 `frozen` 的 13.3%。
判据：**设任何「迹 / 记忆 / 窗口」类参数前，先问「反馈最晚多久到」。**

## 7. 处理原则（为什么旧脚本不改）

`test/` 下的脚本是**实验记录**，不是产品代码。改动它们等于篡改记录、破坏 §16 的可复现性。
所以：

1. **旧脚本一律不动**（含 `grow_world` / `grow_talk` / `grow_cond` / `grow_homeo` / `grow_hebb` / `grow_teach` / `grow_func` / `calib5` / `bench_lif2`）；
2. **新脚本从 `net.py` 起**，只写「本实验特有」的常数（约 10~15 个）；
3. 网络参数要改 → **新建 `net2.py`**，不在 `net.py` 上改（否则历史实验不可复现）；
4. 每个新常数必须带 `[标定]` / `[约定]` / `[派生]` / `[需求]` / `[拍]` 标签；标 `[拍]` 的要在本文件第 3/4 节登记。
