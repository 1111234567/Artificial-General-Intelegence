# 持续动力学与有时间要求的双任务控制

研究问题：学习循环连接，能否使持续状态保住任务内容、接受取消/替换，并在没有新提示时按时完成动作？

两条任务流独立到达。每个命令只出现一次，给出任务编号、版本、内容、处理时长和完成窗口。模型必须 BEGIN，等待真实的任务时间，再 FINISH(版本、内容)。执行期间另一任务会到来；原任务也可能取消或被替换。没有 READY、待办列表、进度或合法动作掩码。动作回执只出现一次。环境事件表预先生成，不随模型行为改变。

连续模型只有一条动力学方程：`dx/dt = -x + W tanh(x)`；事件到达时 `x += B u`。比较冻结 W 和训练 W，再用收到相同事件与 elapsed time 的 GRU 作对照。状态只在独立长流边界清空，TBPTT 边界仅截断梯度。

此项使用有监督 BPTT，不是 Predictive alignment 论文的复现；不是 LIF，不是异步硬件实现。时间为环境中的物理量，执行仍由同步数值模拟器完成。研究背景、实测和局限见[实验报告](../../docs/dynamics-experiment-2026-10-26.md)。

| 文件 | 用途 |
|---|---|
| [world.py](world.py) | 固定事件表、只含脉冲/回执的观察、计时与动作判定 |
| [model.py](model.py) | 冻结/可学习连续循环与时间感知 GRU |
| [run.py](run.py) | 训练、闭环评估、状态扰动与求解器对照 |
| [report.py](report.py) | 汇总配对证据、检查点回放、事后内容诊断和图表 |
| `test_*.py` | 可达性、因果接口、时间、状态与评估测试 |

从仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe -m pytest experiments/dynamics -q
.\.venv\Scripts\python.exe -m experiments.dynamics.run --help
```

主指标同时报告完成率、没有错误尝试的完整请求完成率和 FINISH 精确率。反复猜测或过早尝试后终于成功，不能计作正确计时。小扰动/清空状态另测扰动时已在处理的任务，避免之后的新输入稀释结果。

三种子正式实验已完成：冻结循环/学习循环/时间感知 GRU 的 IID 严格完成率为 **88.56 / 98.66 / 64.17%**。学习循环在长等待下仍降至 **31.42%**；主报告含配置、局限、全部结果和复现命令。

这是有明确队列与计时器解法的受控任务。成功不证明复杂推理、持续权重学习、自评、意识或 AGI。固定容量状态、双任务/四种内容和两个版本值的接口也限定了结论范围。
