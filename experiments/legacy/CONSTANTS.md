# 历史常数台账与机制清单

> **历史工作点记录，非现行参数规则。** 下文保留 2026-10-24 至 10-25 的分类、数值与当时归因；其中「迹必须覆盖反馈延迟」「长期记忆只有连接」等过强判断不能作为当前设计约束或一般机制证明。参数来源标签只说明当时如何记账，并不替代标定或对照。现行结论边界见 [复核记录](../../docs/review-2026-10-26.md) 与 [设计说明](../../docs/design.md)。

> **为何有这份东西：** 2026-10-24 清点发现——同一组网络参数在 27 个脚本里被各抄 10~25 份；
> `grow_goal.py` 一开场就带了 37 个常数，比它替代的 `grow_world.py`（36 个）还多。
> 而 `design.md` §0.3 第 5 条写的是：**不发明新参数——每个常量要么是需求给的，要么有文献出处。**

## 1. 清点（2026-10-24，改前）

| 量 | 值 |
|---|---|
| 常数定义总数（含重复） | **584** |
| 唯一名字 | **161** |
| 重复定义 ≥ 3 次的名字 | **56 个（35%）** |
| 重复最重的 | `V_TH` 27 次 / `N` 25 / `DECAY_V` 25 / `P_GLOBAL` 16 / `N_E` 15 / `OUT_RATE` 15 |
| 死常数（定义但不使用） | **0**（在 `grow_goal` / `grow_world` 中） |

**结论：**问题不是「定义了不用」，而是**重复 + 派生写死 + 纯拍**。
改一个网络参数要改 10~25 处，而且抄的过程中已经漂移（`W_MAX` 10 次里有 `W_MAX_E/W_MAX_I` 两种形态，`TAU` 14 次各不相同）。

## 2. 分类标准（在 `net.py` 里逐行标注）

| 标签 | 含义 | 处理 |
|---|---|---|
| `[标定]` | §11.4.0 手扫标定，有实测数字 | 保留；改它要重跑标定 |
| `[约定]` | 归一化约定（阈值=1，其余相对它） | 保留；不是旋钮 |
| `[派生]` | 由其它常数算出 | **不得作为可调旋钮**（改上游） |
| `[需求]` | 由设计/任务定义（环境设计） | 保留；改它等于改任务 |
| `[拍]` | 无依据，取一个能跑的值 | 保留但**记账**；下一轮优先标定或删 |

## 4. `grow_agent.py` — 本实验特有（17 个，全部带来源）

| 名字 | 值 | 来源 | 备注 |
|---|---|---|---|
| `N_OUT` | 4 | [需求] | 4 个动作 = 4 个输出神经元（§16.10 已证明这个形态能学） |
| `OUT_IDX` | `500..503` | [拍] | 输出神经元（回路里的普通节点） |
| `N_CH` | `N_IN//4` | [派生] | 4 通道 × 25：state / target |
| `IN_RATE` | 0.02 | [拍] | 输入放电率基准 |
| `GAIN` | 0.8 | [拍] | 观测 → 输入率的调制深度 |
| `SIDE_INH` | 1.5 | [拍] | 输出间侧抑制（`grow_talk` 的值） |

| `A_TAU` | 20.0 | [拍] | 输出放电率 EMA（对应步级反馈） |
| `T_ACT` | 5 | [需求] | 动作窗口（§14.6：行为是一个事件窗口；§16.16 从 20 改为 5 → 每 episode 47 个决策） |
| `T_EP` | 240 | [需求] | 每个 episode 的步数（§16.16 从 120 改为 240） |
| `T_GAP` | 200 | [需求] | episode 间间隙（逼退隐状态，迫使依赖连接） |
| `K_EP_TASK` | 5 | [需求] | 同一目标持续的 episode 数 |
| `V_MAX` / `OBS_LO` / `OBS_HI` | 100 / 10 / 90 | [需求] | 值域与采样区间 |
| `ACTIONS` | `[1,-1,10,-10,0]` | [需求] | 5 个离散动作（§16.16 加入「不动」）；旧 4 个的版本留在 `ACTIONS_OLD` |
| `SURPRISE_K` | 10.0 | [拍] | 归因门的尺度（预测误差 / K，clip 到 [0,1]） |
| `BRIDGE` | 0.15 | [拍] | 桥接强度（中性事件 = 值发生变化） |
| `ISOLATE_THRESH` | 0.3 | [拍] | 「本 episode 活跃过」的判定阈值（迹） |

小计：**17 个**（拍 8 / 需求 8 / 派生 1）。

> **这个「冲突」已在 §16.16 定性：不是样本量不足，是任务在参数上不可完成。**
> `T_EP=120` + `T_ACT=20` 只给 6 个决策，而目标差距 30~40 —— 永远到不了。改成 `T_EP=240` + `T_ACT=5`（47 个动作）后，线性基线 99.8%、脉冲网络 36.2%。
> 仍然成立的那一半：结构更新「每任务一次」意味着 150 episode 只有 **150 次更新**（`grow_talk` 是 800 次）——但它是次要因素（§16.15 的 `no_gate` / `no_isolation` 对照已排除）。

**场次四 §五「三个必须同时到位的量」：** `m` ✅ / 压力 ✅（本机真文件）/ **隔离 ✅**。

### 本轮新增一条：全部对齐之后仍然学不到（`docs/experiments.md` §16.15）

`grow_agent`（150 episode × 8 种子）：base 4.8% / frozen 5.3% / no_gate（m≡1）4.7%，
`依据密度` 均≈ 0.47（随机）。**所以机制对齐不是瓶颈。**
对照排除了两个候选：不是 m 大小（m≡1 也一样），不是隔离（无差异）。
剩下的候选（未验证）：**接口拓扑与任务的匹配**（`grow_talk` 的 75% 靠的是 `out_i 只连块 i` 的拓扑偏置）
与**样本量**（每任务只一次更新 = 150 次，而 `grow_talk` 是 800 次）。

### 本轮新增的一个重犯错

迹的时间常数：`grow_talk`（§16.10）已经用数据证明「`delay=50` 学不到，因为 τ=20」，
我在 `grow_goal` 里又用了 τ=20，而 episode 是 120 步——**奖励到达时迹已衰减到 0.007**。
改成 τ=100 后 A 组 +3.8 pp（8.7% → 12.5%），但仍低于 `frozen` 的 13.3%。
判据：**设任何「迹 / 记忆 / 窗口」类参数前，先问「反馈最晚多久到」。**

## 8. 处理原则（为什么旧脚本不改）

`test/` 下的脚本是**实验记录**，不是产品代码。改动它们等于篡改记录、破坏 §16 的可复现性。
所以：

1. **旧脚本一律不动**（含 `grow_world` / `grow_talk` / `grow_cond` / `grow_homeo` / `grow_hebb` / `grow_teach` / `grow_func` / `calib5` / `bench_lif2`）；
2. **新脚本从 `net.py` 起**，只写「本实验特有」的常数（约 10~15 个）；
3. 网络参数要改 → **新建 `net2.py`**，不在 `net.py` 上改（否则历史实验不可复现）；
4. 每个新常数必须带 `[标定]` / `[约定]` / `[派生]` / `[需求]` / `[拍]` 标签；标 `[拍]` 的要在本文件第 3/4 节登记。
