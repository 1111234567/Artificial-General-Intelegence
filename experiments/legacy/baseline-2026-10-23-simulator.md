## 结论

1. **草案的「本机 CPU 小时级」偏悲观约 2 个数量级。** 实测：单个体 N=1000、带可塑性、10⁵ 步 = **4.3 秒**；10⁷ 步 = **7.2 分钟**。N=2000 分别是 16.7 秒 / 27.8 分钟。

2. **GPU 单个体比 CPU 慢 6 倍。** B=1 时 0.1353 ms/步 vs CPU sparse 0.0226——kernel launch 开销主导（每步一次小 matmul）。逐时间步仿真在小网络上不适合单个体上 GPU。

3. **GPU 只在批量时赢**，且需要 B ≥ 16 才抵得过 launch：B=64 快 9 倍，B=256 快 33 倍。

4. **可塑性在大 batch 上成为瓶颈。** N=2000/B=256 时，带资格迹 + 权重更新的成本是无学习的 **10.5 倍**。原因是迹张量是 (B, E)，B×E 元素每步三次读写 + 一次 reduce，受内存带宽限制，随 B 线性增长。

5. **事件驱动在纯 numpy 下只值 1.25~1.92 倍**（活跃边 15~383 / 总数 10000，理论上该省 26~660 倍）。省下来的遍历被索引构造开销（`repeat`/`cumsum`/`arange`）吃掉了。→ **脚本语言里不值得为事件驱动增加实现复杂度**；要拿这个收益就得下手写 kernel（C++/CUDA）或 numba。

6. **稠密与稀疏的交叉点在密度 ≈5%**（N=1000、numpy）。低于 5% 用稀疏、高于 5% 用稠密。阶段 A 的密度搜索范围是 0.5%~10%，**跨越了交叉点，实现需要两条路径按密度选**。

## 对实验设计的直接影响

**阶段 B（少个体、长步数）→ 用 CPU numpy sparse。** 简单、够快、无 GPU 复杂度，10⁷ 步是个位数分钟。

**阶段 A（200~500 个体并行无学习评估）→ GPU batch 有 33~40 倍优势，但有一个约束：** batch 的前提是**所有个体共享同一个权重矩阵**（同一个 `s @ W.t()`）。草案 §11.4 的基因含「节点数 100~2000」与「连接密度 0.5%~10%」——个体间 N 和 E 都不同，**无法装进同一个 batch**。

→ 要享受 batch，阶段 A 的基因必须收窄到「固定 N、固定 E，只变连接模式与 τ 分布」。这与 S8（基因的丰度）直接冲突，需要拍板。

## 未测（本基线不覆盖）

- **异质 τ**：把标量 `decay` 换成 `(N,)` 数组，机制上只是一次数组乘替掉标量乘，预计开销可忽略——但**未实测**。
- **线性探针 / 状态记录**：探针在检查点做，不进时间步循环，预计不改变 per-step；但每 100 步 clone 一次状态（`record=True`）未测。
- **手写 kernel**：C++（AVX2）或 CUDA 常驻 kernel 能绕开「索引构造」和「launch 开销」两个瓶颈，事件驱动的真实收益可能在那里。**未做**。
- **稀疏度更高的网络**（>10%）与**多层/分群拓扑**：未测。
- **完整可塑性规则**（STDP 三因子 / e-prop）：只测了资格迹 + 简单累加写回，不是真实学习规则的成本。
