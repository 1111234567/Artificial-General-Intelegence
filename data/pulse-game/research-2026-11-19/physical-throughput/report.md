# 实际物理评分吞吐独立复核

RTX 4060 Ti（8 GB）、i5-14600KF（14 核、20 逻辑线程）、Windows。GPU 计时每批 1,024 个来自同一冻结遗传检查点的候选，每个场景 48 对同生反事实世界，固定场景每个身体 36 回合。两路输入、动作物理和奖励完全相同。每级做 12 个随机平衡 ABBA/BAAB 块。表中是块内均值的中位数、几何成对加速比和按顺序分层重抽整块的 95% 区间。区间反映此机此组输入的重复运行波动。

| 计时范围 | 旧路径中位 | 新路径中位 | 旧耗时 ÷ 新耗时［95% 区间］ |
|---|---:|---:|---:|
| CUDA event，设备数据常驻且输出预分配 | 103.146 ms | 87.257 ms | 1.180× [1.178, 1.183] |
| 常驻世界评分，同为 64 候选/分块 | 112.443 ms | 94.482 ms | 1.189× [1.185, 1.193] |
| 常驻世界评分，沿用各自分块设置 | 112.659 ms | 87.924 ms | 1.284× [1.280, 1.287] |
| 含世界生成与预取的流水线，沿用各自分块设置 | 0.934 s | 0.776 s | 1.224× [1.203, 1.246] |

端到端每次依次评分 6 批，每个世界的回合数为 36, 40, 42, 34, 34, 62。含一个 CPU 工作者的世界生成、容量为 2 的预取队列、填充和排空、CUDA 世界与感受器生成、基因解码、评分还原和选择排名。常规分块上限为旧 64、新 2048，故新路径每次整批提交。两边都预热，计时不纳入首次 JIT、遗传更新、独立验证和检查点落盘。CUDA event 用常驻世界、已解码候选和预分配输出，仍可能包括连续 launch 的间隔。常驻评分还含基因上传、设备分配、归约和下载分数。

端到端吞吐约 6,578 → 7,920 候选/秒。每批 CPU 世界准备的中位耗时为旧 54.94 ms、新 61.38 ms，主线程等世界分别 0.01 ms 与 0.01 ms。准备与设备执行可重叠。

## 逐拍与计分一致性

| 对照 | 双通道逐拍动作不同 | 末端位置/速度不同 | 接触方向、拍、奖励各自不同 |
|---|---:|---:|---:|
| CUDA warp 诊断副本 ↔ 旧 CUDA | 0/491,520 | 0/61,440 | 0/30,720 / 0/30,720 / 0/30,720 |
| 原生 NumPy ↔ 旧 CUDA | 0/491,520 | 0/61,440 | 0/30,720 / 0/30,720 / 0/30,720 |
| 融合 + warp 诊断副本 ↔ 旧 CUDA | 0/491,520 | 0/61,440 | 仅留整数计数归约 |

三套动作对拍各用 8 个候选 × 16 对世界。旧 CUDA 改为仅记录动作与末端的诊断副本，在已有输出字段的结果不同计数均为 0。NumPy 规则增益最大绝对误差 8.11e-06。融合分数的原始整数计数与 NumPy 不同 0/1,536，加入诊断输出前后不同 0/1,536。

完整流水线世界的融合与旧实现原始整数分数不同 0/1,179,648，最终浮点分数不同 0/24,576（最大绝对差 0）。稳定排序的候选名次不同 0/6,144，入选集合不同 0/504 （按每岛候选位置计），获胜候选不同 0/24，获胜候选的精确整数适应度不同 0/24。

## 小批量原生动作吞吐

同一场景和个体，8 候选 × 16 世界对 × 36 回合。四方法轮换各跑 8 次。NumPy 每个进程只用 1 个 BLAS 线程，Windows 调度器可迁移进程。GPU 时段从已构建的设备常驻世界评分到分数回到 CPU。NumPy 用原生身体闭环并汇总同样计数。各方法在计时前构建同一世界，进程启动与环境构建耗时另外保存。

| 方法 | 中位每批 |
|---|---:|
| NumPy，一进程 | 1013.338 ms |
| NumPy，四进程 | 371.479 ms |
| 旧 CUDA 详细评分 | 9.426 ms |
| 融合 + warp CUDA 评分 | 8.558 ms |

NumPy 四进程对单进程为 2.364× [1.657, 3.078]。GPU 融合评分对四进程为 60.416× [36.113, 140.526]，评分从已准备好的世界开始。完整生成到计分的实际加速使用上表流水线。小批量世界生成 19.7 ms，首次 CUDA 建立和编译 137.7 ms，四进程冷启动加首次评分 4.63 s。

GPU 计时期间整机 CPU 忙比例各阶段为 21.4%, 19.9%, 24.8%, 22.7%，小批量四方法轮换为 19.0%。JSON 含每阶段起止时刻的 GPU 利用率、时钟、温度、系统进程列表及每次计时。窗口观测包含桌面等整机负载，未锁频或绑核。另有一次研究 GPU 并发期间的 NumPy 对照，四进程／单进程为 2.677× [2.111, 3.110]。

原始数据位于同目录 `gpu.json`、`parity.json`、`matched.json` 和 `cpu.json`。`quick-concurrent.json` 与 `smoke-concurrent.json` 是并发背景下的短验收。
